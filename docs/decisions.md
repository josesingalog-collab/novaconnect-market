# Décisions techniques consignées (ADR)

Format : ID · Décision · Raison · Impact. Une décision modifiée doit être marquée SUPERSEDÉE, jamais effacée.

| ID    | Décision                                                                                                                                     | Raison                                                                                                                                                 | Impact                                                                                    |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| D-001 | Montants stockés en `numeric(18,2)` PostgreSQL ; logique métier en `bigint` (unités mineures) via `lib/money.ts`                             | `numeric` exact en base ; PostgREST sérialise numeric en string → pas de perte int8 > 2^53 côté supabase-js ; bigint = arithmétique entière sans float | Lecture/écriture DB passent par `decimalStringToMinor` / `minorToDecimalString`           |
| D-002 | Précision par devise selon ISO 4217 : USD exp 2 (cents), CDF exp 2 (centimes) ; pas de conversion croisée en V1                              | Taux de change non fourni — interdiction d'inventer (§60)                                                                                              | Prix fixés par produit dans sa devise ; seuil retrait défini par devise (`lib/config.ts`) |
| D-003 | Arrondi métier half-up implémenté en entière (`computeCommissionAmount`, bps)                                                                | Déterminisme total des commissions                                                                                                                     | Commission snapshotée dans `order_items` au moment de la commande                         |
| D-004 | Client service-role confiné à `lib/supabase/admin.ts` : `server-only` + règle ESLint `no-restricted-imports`                                 | Sécurité §31/§8 : le service-role ne doit jamais fuiter côté client ni être utilisé pour contourner la RLS par commodité                               | Webhooks/jobs système uniquement                                                          |
| D-005 | `process.env` interdit hors `lib/env.ts` / `lib/config.ts` / configs Next (règle ESLint)                                                     | Validation Zod unique, messages d'erreur propres, inlining NEXT_PUBLIC_* préservé via accès littéraux                                                  | Tout ajout d'variable passe par `lib/env.ts` + `.env.example`                             |
| D-006 | TypeScript renforcé au-delà de strict : `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, target ES2022        | Target ES2022 requis pour les littéraux bigint ; accès indexés sûrs                                                                                    | Quelques vérifications `?? "0"` explicites dans money.ts                                  |
| D-007 | Provider de paiement : interface seule (`services/payments/provider.ts`) + Mock prévu Phase 7. Aucune fausse intégration M-Pesa/OM/Airtel    | Prestataire réel non choisi — information manquante (§60)                                                                                              | Intégration future = nouveau fichier provider, zéro impact sur webhook/commandes/ledger   |
| D-008 | Seuil retrait initial : 20,00 USD uniquement (CDF désactivé jusqu'à décision admin)                                                          | Pas de taux CDF inventé                                                                                                                                | `getMinWithdrawalMinor()` renvoie null → retrait refusé proprement                        |
| D-009 | Ledger immuable append-only avec clé d'idempotence `(entry_type, reference)` UNIQUE                                                          | Double-crédit impossible même si webhook rejoué                                                                                                        | Solde disponible = SUM(ledger) − réservations retraits actifs (RPC atomique, Phase 9)     |
| D-010 | npm ≥ 11 (allow-scripts) : scripts postinstall approuvés explicitement via champ `allowScripts` du package.json (`unrs-resolver`)            | Politique sécurité npm 11 sur cette machine                                                                                                            | Nouvelle dépendance avec postinstall ⇒ `npm approve-scripts <pkg>`                        |
| D-011 | Dossiers `hooks/`, `utils/` créés mais volontairement vides ; pas de composants UI génériques avant besoin réel (§59 anti-sur-développement) | MVP strict validé                                                                                                                                      | Les abstractions n'arrivent qu'au moment où une 2ᵉ utilisation apparaît                   |
